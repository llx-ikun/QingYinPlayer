## 排序预设一览（13 条）

```
自定义顺序
─────────
最近导入              导入时间（早→晚）
─────────
文件大小（大→小）      文件大小（小→大）
时长（长→短）          时长（短→长）
─────────
标题（A→Z / Z→A）  艺人（A→Z / Z→A）  专辑（A→Z / Z→A）
```

设计要点：
- 排序 id 形如 `size:desc`，`SortPreset` 同时携带 `key`/`desc`/`label`/`group`，UI 与排序逻辑共用一份定义；
- 旧式纯维度 key（`added`/`title`…）会被归一化，旧代码或旧设置传入不会失效；
- **大小未知（文件丢失/读不到）的条目在升序和降序下都排在最后**，不会被顶到最前；
- 各视图分别记住上次排序，切走再切回不会被打回默认值。

## 顺带修掉的 4 个既有缺陷

这 4 个问题都不是本次需求的一部分，是截图比对 + 几何探测暴露出来的：

1. **列头与数据行逐列错位（最多 48px）**
   列头比行少 2 个间距位；更隐蔽的是弹性列宽度受 `sizeHint` 影响（列头「歌曲」30px vs 行内歌名不定），同 stretch 也算出不同宽度。
   修法：列头改用与行完全相同的槽位（含占位槽）+ 弹性列 `sizePolicy=Ignored`。

2. **所有固定尺寸按钮虚胖 20px**
   基础规则 `QPushButton{padding:6px 10px}` 会叠加在 `min/max-width` 上：34→54、40→60、46→66、36→58。
   后果：播放键 `border-radius:20` 落在 60×52 上变成椭圆；行内 ♥/⋯ 声明 28 实际 48，两个按钮多吃 40px 直接导致列漂移；浮动条超宽。
   修法：固定尺寸选择器统一 `padding: 0`。

3. **左下浮动条被裁（v2.1.2 起就坏）**
   绝对定位的子控件不会自动取 `sizeHint` 宽度，`_position_float_bar()` 只 `move` 不 `adjustSize`，宽度停在默认 100px → 「正在播放/数据目录/设置」全被父控件裁掉，只剩几个空图标。

4. **侧边栏昵称截断**
   徽标 `setFixedWidth(56)` 把整个 `QVBoxLayout` 的最大宽度压到 56，「音乐爱好者」被省略成「音乐爱…」。
   修法：徽标改 `SizePolicy.Maximum` 并套进带 `addStretch(1)` 的行，昵称用 `Ignored` 跟随可用空间（56→156px）。
