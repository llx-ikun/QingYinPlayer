1. 歌词右键 → **「AI 对齐歌词（逐字）」**（需要这首歌已有带时间轴的 .lrc）
2. 第一次会问「要下载 142MB 模型吗」，下完就永久离线
3. 一首 4 分钟的歌在 CPU 上大约几十秒
4. 不满意 → 右键「清除本曲逐字数据」，立刻退回 v2.9.2 的匀速扫光

全库批量对齐、清空字级数据。

## 核心决策（以及为什么）

### 1. 先做数据层和渲染，再做模型

C（渲染）只依赖 A，能用手写的假逐字数据验证；如果先做 B，渲染层还没消费 `words`，
引擎产出完全不可见，无法端到端验证。所以我调整了 TASK 顺序：**A → C → B → D → E**。

### 2. 渲染层一行画法都没改

`_draw_line` 的接口只有一个整数 `typed`（`text[:typed]` + 按字宽算交界 x）。
所以「逐字对齐」只需把 `typed` 的来源从「线性插值」换成「按字时间窗求解」——
这是零风险的根。视觉探针实测（同一句、同一进度 2000ms）：

- 线性插值：亮到第 4 字「随记忆一」
- 逐字时间窗：亮到第 7 字「随记忆一直晃到」

### 3. 关键取舍：宁可不给，也别给错

L5 自检（匹配率 <55% 或平均概率 <25% → 放弃）不是摆设。真机验证：
拿合成音频（**没有人声**）跑 whisper-base，它幻觉出「你认识了我吗」，
probability 只有 0.02~0.48 → L3 匹配率 0% → L5 判定失败、**不写盘**。
没有这道闸，用户会得到一份「静静地错掉」的歌词，比不做还糟。

### 4. 不自动改用户的 .lrc

AI 对齐也能算出**行**时间（`retime_lines()`），理论上能把本地近似对齐的 6.04s 误差
压到亚秒级。但改用户的歌词文件属于破坏性动作，所以本版**不自动写回**：
偏差 >1s 时界面明确提示「行时间偏了 X 秒，建议先用逐句打轴校正」，
而不是假装对齐成功了。

## 踩到的坑（都已在代码注释里写明）

1. **`ctranslate2` 4.8.4 在冻结产物里加载模型必 segfault**（exit 139、零输出、无异常）。
   降到 4.6.0 立刻正常；4.6.0 依赖 `pkg_resources`，所以要 `setuptools<81`。
2. **`--collect-binaries ctranslate2` 必须加**：少了 `libiomp5md.dll` 同样是 segfault，
   不是 ImportError —— 这种失败最难查。
3. **不能把音频路径交给 whisper**：faster-whisper 1.2.1 走 `av.open(metadata_errors=...)`，
   av 19 已删该参数 → 必崩。自己用 miniaudio 解码成 numpy 喂进去。
4. **增强 LRC 的 `offset` 必须同步平移逐字时间**：漏了就是「行高亮到了、字还停在原地」。
5. **`store.tracks` 是 dict 不是 list**：`for track in store.tracks` 拿到的是 id 字符串。
6. **windowed 产物没有 `sys.stdout`**：所以加了 `main.py --check-ai`，报告写
   `%TEMP%\qy_ai_check.txt`。它的存在就是为了证伪第 1 条那个坑。
