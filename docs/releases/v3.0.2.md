# v3.0.2 交付说明 —— 批量 AI 对齐「关不掉」

## 一句话结论

不是偶发卡死，是**五个缺陷**叠成了一条死路。两个是设计问题（停止不通知线程、关闭提示让
你去点一个已经灰掉的按钮），三个只有真机跑才暴露（进度信号参数写错导致进度全死、
中止完队列照跑、`wait(3000)` 超时后没人再触发关闭）。现在「关闭」永远有出路：
点了就请求中止，中止完成自动关窗。真机实测 10.2 秒关闭完成。

## 现场还原

| 截图里的现象 | 真实原因 |
|---|---|
| 「停止」是灰的 | 点过一次就置灰防重复点，但 worker 根本没收到中断请求，还在跑 |
| 「关闭」点了没反应 | `closeEvent` 无条件 ignore，提示改成「先点『停止』再关闭」——而停止已经灰了 |
| 进度条 0%、没有阶段文字 | ①那根条统计的是**首数**（0/6）；②更糟：**进度信号参数写错，每次推送都抛 TypeError**，进度从来没工作过 |

## 改了什么

**中止链路（让它真能停）**

| 层 | 改法 |
|---|---|
| 推理 | `transcribe(..., interrupted=谓词)`：whisper 的 `segments` 是生成器，每段问一次 |
| 下载 | `download_file / ensure_model(..., interrupted=谓词)`：分块检查，`.part` 留着续传 |
| 传导 | worker 传 `self.isInterruptionRequested` 这个**谓词**，不是布尔快照 |

**对话框语义（给它留出路）**

- 「停止」= 请求中止 + 留在窗口看结果；「关闭」/窗口 X = 请求中止 + **完成后自动关闭**
- 点关闭时**同时置 `_stop`**，中止完不会再去跑下一首（这是真机抓出的 bug）
- `_retire()` 改成 `wait(0)` + `finished` 回调 + `_maybe_close()` 收口，**不在 UI 线程阻塞**
- `closeEvent` 检查**所有**活线程（含已退场的），根治「带活线程析构」崩溃
- 中止期间进度推送不再覆盖「正在中止」的说明
- 主动中断不计入失败；进度条改 `%v / %m 首`

**顺手修掉的**

- `LyricsAsrWorker.progress` 由 `Signal(int, str)` 改为 `Signal(str, int, str)`
  → 主窗口单曲对齐的进度提示**也一起恢复了**（之前同样是死的）
- 「没有同步歌词」用循环跳过（原来是递归，全库批量几千首会 `RecursionError`）
- `align_track` 的 detail 兜底会让界面显示「xxx（xxx）」

## 一个必须提醒你的发现（还没改，等你定）

批量里的**英文版**歌曲会失败。`LyricsAsrWorker.language` 默认写死 `"zh"`，给英文歌
强行按中文识别，结果与歌词对不上，被判 `low_confidence` 放弃。截图第 1 首
「Blazing Heart (英文版)」就是这类。

两条路：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 让 whisper 自动识别 | `language=None` | 唱歌的语种识别不准，中文歌偶尔被判成日/英 |
| B. 按歌词字符比例猜 | 汉字占比低于阈值 → 传 None | 中英混排、罗马音歌词会猜错 |

我倾向 B + 右键菜单手动指定语种。这是产品决策，不塞进这次修 bug。
